# 运行时分工与性能

`Asset.cs`从声明模型的MOD读取资源并检查格式，每个`MechanicalModelDef`缓存一份只读模型。`PreparedGeometry.cs`在加载时合并重复顶点、计算法线并建立候选轮廓边。

`Animation.cs`根据参数计算局部变换，先处理父节点，再处理子节点。每个节点有姿态修订号；查询挂接点不会清除绘制器需要的更新标记。`VisualInstance.cs`比较修订号，仅更新姿态发生变化的部件。旋转未变时复用法线和朝向结果，静止模型复用现有几何。

`MeshBuffers.cs`分别处理1.6的Unity缓冲和1.7的Waylith缓冲。1.7使用原生`CpuMeshData`后，应继续通过该缓冲更新；混用兼容层的`vertices`、`uv`、`triangles`属性或`Clear`会复制数组或改变缓冲状态。两个版本采用相同的投影和描边规则，分别编译并在对应游戏中测试。

每个实例绘制两个网格，分别用于表面和可见轮廓。顶点与索引数组按容量预分配，有效轮廓索引连续存放。轮廓半宽为0.035格，折边半宽为0.018格；材质色板提供32档亮度。三角面数、轮廓边数、活动部件数和同屏实例数量都会影响开销。

框架负责模型、动画、绘制和保存，游戏规则由使用框架的MOD实现。制作工具在开发阶段运行。玩家无需安装Python或建模软件。

目前完成了三个不同模型同时运行的功能检查，尚未进行多实例性能基准测试。测量时可分别记录静止、单关节运动、整体旋转，以及10个、50个同屏实例的耗时和内存，并注明游戏版本、模型面数和绘制后端。
