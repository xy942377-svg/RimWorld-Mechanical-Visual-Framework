# 运行时分工与性能

Asset.cs 从消费 MOD 加载模型并检查格式；每个 MechanicalModelDef 缓存一个不可变资产。PreparedGeometry.cs 建立去重顶点、法线和候选边，只在模型加载时执行。

Animation.cs 根据参数组合节点局部变换，并沿父先子的顺序得到姿态。每个节点有修订计数，挂接点查询不会消耗绘制需要的“姿态已改变”信息。VisualInstance.cs 缓存上一轮修订号，仅更新发生变化的部件；旋转未变时复用法线光照和朝向结果。原地不动的模型不重建几何。

MeshBuffers.cs 隔离 1.6 Unity 与 1.7 Waylith 的缓冲上传。1.7 在原生 CpuMeshData 上操作后，不可混用兼容层 vertices、uv、triangles setters 或 Clear；混用会复制大数组或改变缓冲状态。两版使用相同投影和描边契约，分别编译 DLL。修改此文件时务必在对应真实游戏验证，普通桌面 .NET 测试不能代替。

每实例两次网格绘制（表面+可见轮廓），固定数组、可见轮廓索引压紧。没有降低帧率、跳过角度或静态帧贴图切换。轮廓线保持原型的粗度：轮廓半宽 0.035 格，折边半宽 0.018 格。材质色板使用 32 档亮度。细节、面数、轮廓边数和动态实例数量均会影响开销。

Core 不含武器参数、炮塔目标搜索、发电逻辑或盾的机制。Examples 只注册三个模型和测试建筑。Tools 只在制作时运行；Python 与建模软件不进入玩家依赖。组件主要负责生命周期、正常 tick、保存和可选作者控制面板。

目前没有给新框架作多实例极限性能承诺；旧原型的性能结果不能直接当作本版本实测。调整前先分开测：空闲姿态、单个关节运动、整组旋转、10/50 个同屏实例，并记录实际游戏版本、面数和渲染后端。避免只根据磁盘大小推断运行内存。
